# LAST WORD

古地図を進み、単語からカードを合成する一人用ブラウザ・ローグライク。対人戦・アカウント登録・サーバーは不要です。

## 起動

Node.js 22以降で実行します。

```sh
npm run dev
```

表示されたURLをブラウザで開いてください。配布用ファイルはすべて `dist/` にあり、Phaserも同梱済みです。HTMLの直接ダブルクリックではなく、HTTPサーバーを使います。

## 遊び方

- 地点を選んで移動し、中央ボスを倒す。
- FIREなどの基本語1個に、DOUBLEなどの追加語を最大3個組み合わせる。
- カードの消費エナジーは単語コストの合計。FIREは1、DOUBLE FIREは3。
- 素材は合成時に消費。完成カードはデッキに残り、戦闘で繰り返し使える。
- 毎ターンのエナジーは3。集中で＋2、代わりに時間＋1。
- 英語の意味・敵の予告を読み、報酬や防御を増やす。

| 行動 | 時間 |
| --- | ---: |
| 移動 | 3 |
| ターン終了・集中・単語購入 | 1 |
| 合成 | 2 |
| 休息 | 4 |

時間経過で安全圏が中央へ縮小し、圏外では行動時にダメージ。時間150またはHP0で終了します。訪問済み地点の報酬・敵・休息は復活しません。読解中や待機中には時間が進まないため、英語を読む速さで不利になりません。

## 内容

- 壁のない古地図3種類（火山・雪山・裂け目）
- 選択キャラ2人、魔物7種類と中央ボス
- 単語12種類、カード合成、デッキ整理、鍛冶場、休息、碑文
- 英単語の意味・例文・読み上げ・誤答に応じた復習出現
- オートセーブ、途中再開、周回をまたぐ単語帳
- マウス・タッチ・キーボードのボタン操作、縦横レイアウト

カード名はゲーム内の合成表記です。`POWER DOUBLE FIRE`などを自然な英文として教えるものではありません。例文は単語帳に別途収録しています。読み上げの声は端末・ブラウザによって異なります。

## GitHub Pages

1. 空のGitHubリポジトリを作成し、このフォルダ一式を `main` にpush。
2. リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定。
3. **Actions → Test and deploy Last Word → Run workflow** を実行。

通常のpushでは自動テストを実行します。`.github/workflows/pages.yml` を手動実行すると、テスト後に `dist/` を公開します。初回はPages設定が必要です。公開すると同梱画像もアクセス可能になるため、公開前に素材の権利をご確認ください。

## 開発・検証

```sh
npm run check
npm test
```

通常の実行・テストに追加インストールは不要です。Phaserを更新する場合のみ `npm ci` を使い、`node_modules/phaser/dist/phaser.min.js` とライセンスを更新してください。

| ファイル | 役割 |
| --- | --- |
| `dist/engine.js` | シード乱数、戦闘、合成、報酬、時間・セーブ |
| `dist/data.js` | 単語、例文、敵、マップ定義 |
| `dist/world.js` | Phaserの地図・キャラ・演出 |
| `dist/app.js` | DOMのHUD・画面操作・保存 |
| `dist/style.css` | レスポンシブUI |
| `tests/engine.test.mjs` | 18件のゲームロジックテスト |

保存先はブラウザのLocalStorageです。ブラウザデータ削除、異なる端末・URLへの移動でセーブは共有されません。オンライン対戦・課金・解析送信はありません。装飾フォントのみGoogle Fontsを利用し、未接続時は端末のフォントにフォールバックします。

## 素材とライセンス

既存素材はユーザー指定のGoogle Drive「ChatGPT」フォルダから利用しています。出典は `ASSETS.md` を参照。素材の再配布ライセンスは未確認のため、このプロジェクト全体にオープンソースライセンスは付与していません。PhaserはMITライセンス（`dist/PHASER-LICENSE.md`）。

v0.1のプレイ可能なプロトタイプです。自動テスト18件とデスクトップの合成→戦闘→報酬→保存再開を検証済み。長期的な難易度調整や実機タッチ・全ブラウザ検証は今後の対象です。

## 戦闘画面と画面遷移の確認

背景は探索・戦闘とも同じ全面キャンバスを使用します。描画サイズは親領域の ResizeObserver だけで更新し、Phaser の自動 RESIZE と二重に変更しません。左右のカメラ用余白は `combat.css` の `--screen-left` / `--screen-right` で共通管理します。HP・状態表示の位置をキャラ描画にも使うため、画面回転時も足元の位置が揃います。

Playwright と Chromium が利用できる開発環境では `npm run test:ui` で画面遷移を確認できます（通常の `npm test` にはブラウザは不要）。スマホ横・小型スマホ・PC・TV・4K・縦画面で実際に戦闘→報酬→マップ→次の戦闘を操作し、描画サイズ・HPと手札の重なり・画面回転・左右のカメラ用余白を検査します。画像は `artifacts/ui/` に出力します。必要に応じて `PLAYWRIGHT_MODULE` と `BROWSER_EXECUTABLE` で既存の実行環境を指定できます。

### 操作性の改善

- 戦闘の「山札」「捨札」でカードを確認できます。名前順の表示で、ドロー順や乱数状態は変わりません。
- メニューから遊び方、合成からデッキを開いた後は、閉じると元の画面に戻ります。
- モーダル表示中は背後への入力を止め、閉じた後やカード使用後もキーボードの選択位置を保ちます。
- 使用できないカードは「エナジー不足」、集中使用後は「集中済み」と表示します。

開発時は [awesome-gamedev-agent-skills](https://github.com/gamedev-skills/awesome-gamedev-agent-skills) の `phaser-core`、`game-ui-ux`、`card-game` をタスクに合わせて参照します。既存の Phaser 3.90 を維持し、画面遷移・安全領域・カード領域の分離を検証します。
